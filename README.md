# Наші фінанси: трекер Олі й Марка

Спільний фінансовий трекер на Beancount 3. Імпортує дві банківські виписки (Олі й Марка), звіряє їх з банком через `bean-check` і показує щомісячний звіт: витрати за категоріями, норму заощаджень, фіксовані й змінні витрати. Оля й Марко входять з телефону кожен під своїм логіном, додають готівку і задають ліміти на категорії; сторінку можна встановити на головний екран (PWA). Кожен бачить свої витрати і лише спільні витрати іншої людини.

Усі дані в репозиторії вигадані: це навчальне завдання (WIT 5.0).

## Перевірка однією командою

Потрібен [uv](https://docs.astral.sh/uv/getting-started/installation/).

```sh
uv run python check.py
```

Команда перезбирає `transactions.beancount` з обох виписок, запускає `bean-check main.beancount` і друкує контрольні цифри. Очікуваний результат:

```
2. bean-check main.beancount
   без повідомлень

3. Змінні витрати (без #fixed), PLN
   хто    місяць            є  має бути
   Оля    серпень     2195.21   2195.21  OK
   Оля    вересень    2582.42   2582.42  OK
   Марко  серпень     1855.57   1855.57  OK
   Марко  вересень    2432.83   2432.83  OK

Усе збігається.
```

Тести приватності (Марко не бачить особистих записів Олі й навпаки):

```sh
uv run python -m unittest -v
```

Змінні витрати = усі витрати без тегу `#fixed`. Фіксовані в Олі: оренда, ZTM, Netflix, Spotify, Claude.ai, Play. У Марка: Orange (інтернет і телефон), PGE, Zdrofit, YouTube Premium.

## Що де лежить

| Файл | Що робить |
|---|---|
| `data/statement.csv`, `data/marko-statement.csv` | Виписки Олі й Марка (вигадані), 1 серпня — 15 жовтня 2026 |
| `rules.csv`, `rules-marko.csv` | Правила категорій для кожного банку; колонка `спільна` ставить тег `#shared` |
| `limits.csv` | Ліміти на місяць: `рахунок,ліміт`. Можна правити руками або на екрані «Ліміти» |
| `import.py` | Читає обидва формати CSV, пише `transactions.beancount` з перевіркою залишку банку |
| `main.beancount` | Рахунки по людях (`Expenses:Марко:Продукти`), збережені запити, `include` |
| `cash.beancount` | Готівка, додана з телефону. Створюється автоматично, у git не потрапляє |
| `check.py` | Команда перевірки вище |
| `report.py` | Звіт; `uv run python report.py` пише статичний `report.html` |
| `app.py`, `cashbook.py`, `wsgi.py` | Веб-застосунок: вхід, звіт, форма готівки, ліміти |
| `test_privacy.py` | Тести: хто що бачить |
| `make_env.py` | Створює `.env` з секретним ключем і хешами паролів Олі й Марка |
| `static/` | Маніфест, іконки, service worker для встановлення на телефон |

## Запуск на своєму комп'ютері

```sh
uv run python make_env.py            # паролі для olia і marko, пише .env
TRACKER_DEV=1 uv run python wsgi.py
```

Відкрити http://127.0.0.1:5050 (вхід `olia` або `marko` з паролями з `make_env.py`). `TRACKER_DEV=1` дозволяє http без HTTPS, тільки для локальної перевірки. Fava окремо, як на воркшопі: `uv run fava -p 5050 main.beancount`.

## Публікація на PythonAnywhere (безкоштовно)

1. Зареєструвати безкоштовний акаунт Beginner на [pythonanywhere.com](https://www.pythonanywhere.com/). Адреса буде `https://ЛОГІН.pythonanywhere.com`.
2. **Consoles → Bash**, виконати по черзі:
   ```sh
   git clone https://github.com/kkocherzhenko/tracker-finance.git
   cd tracker-finance
   mkvirtualenv --python=python3.12 tracker
   pip install -r requirements.txt
   python import.py
   python make_env.py
   ```
   `make_env.py` питає пароль для кожного з двох логінів (`olia`, `marko`) і пише `.env` з хешами. Відкритих паролів ніде не лишається. Перевіряючим даємо паролі обох логінів: кожен бачить свої витрати і лише спільні витрати іншої людини, тож контрольні цифри Олі видно під `olia`, а Марка під `marko`.
3. **Web → Add a new web app → Manual configuration → Python 3.12.**
4. На сторінці застосунку:
   - **Virtualenv:** `/home/ЛОГІН/.virtualenvs/tracker`
   - **Source code:** `/home/ЛОГІН/tracker-finance`
   - **WSGI configuration file:** відкрити й замінити весь вміст на
     ```python
     import sys
     sys.path.insert(0, "/home/ЛОГІН/tracker-finance")
     from wsgi import application
     ```
   - **Security → Force HTTPS:** увімкнути.
5. Натиснути **Reload**. Відкрити `https://ЛОГІН.pythonanywhere.com` на телефоні, увійти, у меню браузера вибрати «На екран Додому» (iPhone) або «Встановити застосунок» (Android).
6. Безкоштовний застосунок треба продовжувати раз на місяць кнопкою **Run until 1 month from today** на вкладці Web.

Оновити код на сервері: `cd ~/tracker-finance && git pull && python import.py`, потім **Reload**. Записи готівки в `cash.beancount` при цьому не зачіпаються. Якщо ліміти міняли з телефону, `limits.csv` на сервері відрізняється від git: перед `git pull` зробити `git stash`, після — `git stash pop`.

Після оновлення з версії з одним спільним входом (`TRACKER_USERS`) треба ще раз запустити `python make_env.py`.

## Безпека

- **Без входу немає даних.** Кожна сторінка, крім входу, маніфесту й іконок, перенаправляє на `/login`. Service worker не кешує сторінок з даними.
- **Кожен бачить своє і спільне.** Запис спільний, якщо має тег `#shared` (для імпорту його ставить колонка `спільна` в правилах: зараз це оренда й продукти; для готівки — перемикач «Особиста / Спільна»). Сервер відкидає особисті записи іншої людини до будь-яких підрахунків (`report.visible`), тож у вкладці іншої людини лише її спільні витрати, без доходів і лімітів. Ліміти кожен бачить і змінює лише свої. Готівку можна записати лише на себе.
- **Fava у веб-застосунку немає.** Її редактор показує й дозволяє переписати сирі файли обліку, тобто й чужі особисті записи; надійно обрізати це не можна. Fava лишається для роботи на своєму комп'ютері (`uv run fava -p 5050 main.beancount`).
- **Секрети лише в змінних середовища.** `SECRET_KEY`, `TRACKER_HASH_OLIA` і `TRACKER_HASH_MARKO` (хеші паролів scrypt) читаються з середовища; на сервері їх задає файл `.env`, який створює `make_env.py` і який не потрапляє в git.
- **Лише HTTPS.** PythonAnywhere видає сертифікат для `*.pythonanywhere.com`; Force HTTPS на сервері плюс перенаправлення http→https і заголовок HSTS у самому застосунку. Cookie сесії `Secure`, `HttpOnly`, `SameSite=Lax`, форми із CSRF-токеном.
- **Лише вигадані дані** в репозиторії й на сервері.
- **Додатково: обмеження спроб входу** (5 невдалих спроб з однієї адреси → пауза 5 хвилин). Навіть для двох людей адреса `*.pythonanywhere.com` публічна, і боти перебирають паролі на всьому, що знаходять; це кілька рядків коду і нуль зусиль для Олі й Марка. 2FA і шифрування полів не додавали: для двох людей із вигаданими даними це ускладнення без користі.

## Де побачити додану готівку

Після збереження в «Нова транзакція» застосунок повертає на звіт потрібної людини і місяця: готівкова витрата є в блоці «Готівка» на вкладці «Витрати» і входить у суми категорій. У самому обліку вона лежить у `cash.beancount` з тегом `#cash` (у веб-застосунку цей файл не відкривається, лише локально).

## Що спрощено

- Спільне чи особисте задається для цілої категорії в правилах, не для окремої операції з банку.
- Ліміти — на категорію однієї людини; спільного ліміту «продукти на двох» немає.
- Готівку записуємо як витрату з рахунку `Assets:<людина>:Готівка` без звірки залишку готівки.
- Хто кому винен за оренду й продукти (функція 9) не рахуємо.
- Безкоштовний тариф PythonAnywhere: одне веб-застосування, обмежений процесор, продовження раз на місяць; перше відкриття може бути повільним.
