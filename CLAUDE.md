# Правила проєкту

Спільний фінансовий трекер Олі й Марка на Beancount 3 з веб-доступом з телефону (`app.py`, хостинг PythonAnywhere). Для кого він і що має показувати, описано в `PERSONA.md`. Документи проєкту: `PRD.md` (що будуємо), `IMPLEMENTATION_PLAN.md` (кроки), `PROGRESS.md` (що вже зроблено і що далі). Якщо їх ще немає, вони зʼявляться на початку роботи.

Людина, з якою ти працюєш, не має досвіду розробки. Пояснюй коротко і без жаргону: що зроблено, навіщо і як це перевірити.

## Жорсткі правила
- Папка `data/` лише для читання. Нічого в ній не змінюй, не переноси, не видаляй і не пиши туди результати.
- Після кожної зміни в обліку (`main.beancount`, `transactions.beancount`, `import.py`, `rules.csv`, `rules-marko.csv`) запускай `uv run python check.py` (імпорт, `bean-check`, контрольні цифри). Зміна не готова, доки перевірка не пройде без жодного повідомлення. Показуй людині результат перевірки.
- «Готово» означає, що перевірка пройшла, а не що код написано.
- Після кожного завершеного кроку онови `PROGRESS.md` і зроби коміт у git з коротким описом українською.
- Дані в цьому репозиторії вигадані (навчальне завдання), тому `data/`, `transactions.beancount` і `report.html` комітимо: перевіряючий клонує репозиторій і запускає одну команду. Справжні виписки сюди не потрапляють ніколи.
- У git ніколи не потрапляють `.env` (секретний ключ і хеші паролів) і `cash.beancount` (готівка, додана з телефону на сервері). Паролі й ключі живуть лише в змінних середовища, ніколи в коді.
- Без входу застосунок не показує жодних даних; працює лише через HTTPS. Нові сторінки з даними закривай тим самим входом (`require_login` в `app.py`).

## Інструменти
- Python-середовище вже налаштоване через uv (`pyproject.toml`). Усе запускай лише через `uv run …`: `uv run bean-check`, `uv run bean-query`, `uv run fava`, `uv run python …`. Нових пакетів без дозволу людини не встановлюй. Після зміни залежностей онови `requirements.txt` (`uv export --no-hashes --no-dev -o requirements.txt`): його ставить PythonAnywhere.
- Лише синтаксис Beancount 3. Збережені запити пишемо нативною директивою `query`, а не `custom "query"`.
- Fava запускаємо на порті 5050 (`-p 5050`): порт 5000 на macOS часто зайнятий AirPlay.

## Як влаштований облік
- `main.beancount` — опції, відкриття рахунків, збережені запити і рядок `include "transactions.beancount"`. Кожен рахунок, який використовується, має бути відкритий тут директивою `open`.
- `transactions.beancount` генерує `import.py` з `data/statement.csv` (Оля) і `data/marko-statement.csv` (Марко, польський банк: `;`, дати `ДД.ММ.РРРР`, суми `1 234,56`, найновіші рядки зверху) за правилами `rules.csv` і `rules-marko.csv`. Руками цей файл не правимо: він перезаписується при кожному імпорті.
- Правила категорій живуть лише в `rules.csv` (колонки: шаблон, рахунок, фіксована). Шаблон шукаємо в описі операції без урахування регістру. Перемагає перше правило, що підійшло, тому конкретніші шаблони стоять вище (`Bolt Food` перед `Bolt`). Операція без правила йде в `Expenses:<людина>:Без-Категорії`, надходження без правила — в `Income:<людина>:Інше`.
- Рахунки розділені за людьми: `Assets:Оля:Банк`, `Expenses:Марко:Продукти` тощо. Друга частина назви — хто платив; збережені запити групують за нею.
- `cash.beancount` — готівка з телефону (тег `#cash`, рахунок `Assets:<людина>:Готівка`). Пише його веб-застосунок (`cashbook.py`) або форма «+» у Fava; `import.py` його не чіпає.
- Рядки у виписці стоять у порядку банку. Колонка залишку рахується саме в цьому порядку, навіть коли час операцій усередині дня йде не за зростанням. Не сортуй рядки, коли працюєш із залишком (виписку Марка лише розвертаємо).
- Якщо в `data/` кілька виписок і рядки повторюються, однаковий рядок (дата завершення, опис, сума, залишок) рахуємо один раз.
- Назви рахунків: корені англійською (`Assets`, `Liabilities`, `Equity`, `Income`, `Expenses`), нижче — українською, слова через дефіс, без апострофів.
- Фіксовані витрати позначаємо тегом `#fixed`, а не окремими рахунками.
